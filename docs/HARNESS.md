# Harness 任务中心

鲸屿 4.4.0 通过 DeepSeek Harness 官方 SDK profile 执行任务。已对 macOS 的 Harness 0.2.2-rc.3 进行本机联调。它使用已安装的应用及其工具，另开鲸屿拥有的 SDK 会话，不控制或修改桌面版已有聊天。

## 使用

1. 打开鲸屿左侧「Harness 任务」。默认查找 `/Applications/DeepSeek Harness.app`，也可在连接设置中选择已安装应用。
2. 打开连接设置，选择任务工作目录。默认目录位于鲸屿应用数据目录的 `tasks/`，可在 Finder 打开。
3. 选择 Harness 中已经配置好凭据的模型路由：OpenAI 或 DeepSeek 官方；填写该路由对应的模型 ID。默认 OpenAI / gpt-5-mini。
4. 点击「测试 SDK 连接」。握手成功只说明运行时和路由初始化成功，不代表余额、网络或模型推理已验证。
5. 提交一个任务，例如「在当前工作目录生成一份文件清单，保存为清单.md」。任务会显示启动、执行、等待回答、完成或失败；正常调用会产生所选模型的用量。
6. Harness 要求审批或补充信息时，在页面逐次回答。没有自动放行；未知或已失效请求不能授权。
7. 点击停止会关闭本次独立 SDK 运行时。已经执行的文件操作不会回滚；超时和重启后都不会自动重复提交。

模型连接与本机试聊仍使用鲸屿原来的配置；Harness 使用自己的路由和凭据，两套配置独立。人设默认不附带，可勾选「将当前人设提示词作为表达偏好附给任务」；它不会替换 Harness 的原生工具与审批机制。

## 实现与数据

- 通过安装版 Electron 的 Node 模式运行包内官方 CLI：`dsh --profile sdk --patch <鲸屿overlay>`。
- stdio JSON-RPC 使用官方 `initialize`、`session/prompt`、`session/wait` 与 `shutdown`；处理会话事件、审批和用户问题。没有 HTTP 监听端口。
- overlay 在鲸屿数据目录中生成，只声明 OpenAI 适配器凭据引用、工作目录写入和询问审批策略，不包含 Key，也不修改原来的 desktop profile。
- Harness 自行读取其配置的凭据及 `.env`。鲸屿不会导入或复制这些密钥；连接失败应在 Harness 中修复凭据、模型与代理。
- `harness.json` 保存工作目录、路由以及任务内容/结果，不包含模型 Key，但可能包含用户的私有任务资料，不应上传公开仓库。
- 当前每次只运行一个任务。各任务使用新的独立会话；不提供恢复任意既有 Harness 会话的入口。此版本不提供 SDK 的全部 slash command。
- SDK profile 拥有工具清单，不会自动等同于用户的 desktop profile 插件；Office sidecar、第三方插件及额外技能取决于 SDK 的安装配置。
- 审批等待仍计入任务总超时。用户需保持应用运行；关闭会请求停止本次任务。

## 验证

自动化使用可控 stdio 子进程验证握手、结果事件、单次审批、停止、历史与重启状态。另已使用本机官方 Harness 和真实模型，在隔离工作目录创建固定内容的测试文件，并核对磁盘内容与 SDK 完成状态。微信收发未接入，因此此验证不代表已能从微信触发任务。
